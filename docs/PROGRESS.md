### Wiggle test — 2026-11-08

- Sagi: a quick check of heavy machinery, tied to the user and the vehicle. A new record kind `wiggleTests` (table `WiggleTest`, migration `wiggle_tests`, additive): a V / X per item, one optional "Other problems" text at the end, saved with who did it and when (date and time of saving). Event `WIGGLE_TEST` names the items marked X.
- Checklists (`packages/shared/src/wiggle.ts`): steering differs by machine. Loader (articulated): articulation joint and pins, steering cylinders and hoses, full lock both ways. Tracked excavator: both tracks travel and steer, swing / slew ring, undercarriage. Wheeled excavator: full lock, axles and tie rods, swing. Skid-steer: left and right drives, wheels and axle bearings. Every list ends with cameras, LiDARs and communications. "All V" marks everything, then an X is one tap.
- Which types take it is an admin setting (Settings → Record fields → Wiggle test, `AppSetting.wiggleTypes`); loaders, both excavators and skid steers to start. The card shows only on those vehicles, first in the list, with the last test ("Last today", amber when it had an X). The API refuses other types (`no_wiggle_test`) and any answer missing or not on the machine's list.
- Anyone signed in can do one (operators may be viewers) and change their own; editors change any. When an editor saves a test with an X, the panel offers "Report a malfunction" with the text filled in.
- History is the record panel: newest first, dates, search in the notes, "With an X only", row report with each item, Excel export of that vehicle's history (one column per item of its checklist) in the chosen date range; the whole-fleet export has a Wiggle tests sheet.
- Round 2 (Sagi, same day): one steering item ("Steers correctly both ways"); loaders check front, back, left, right and cab cameras, excavators (tracked and wheeled) "Cameras" plus a front-down camera, skid steers "Cameras"; then LiDARs, IMUs, communications signal stability, instruments working; fluids (Full / Missing), mechanical and hydraulic tools (Functional / Requires attention) on every heavy machine. On a PC the highlighted item is answered from the keyboard (V or Y, X or N, by key position so a Hebrew layout works) or the controller's logo button (standard-layout button 16): once is V, twice within 0.5 s is X; "Use another button" picks a different one per device (`fh.wiggleButton`). Sheets now focus a `data-autofocus` control first.
- Not done (Later): wiggle tests don't change the vehicle's status; not in the printed vehicle report or the Excel import.
- Tests: 5 api tests (`test/wiggle.test.ts`) plus the generic record test, 3 e2e (`e2e/wiggle.spec.ts`). Screenshots in `/mnt/project-files/fleet-hub/wiggle/`.

## Decisions

<!-- Stack or design decisions with a one-line reason. -->

- Server is Ubuntu on ARM64: all images and native modules must have arm64 builds; Phase 1 checks the api builds for arm64.
- Docker on the server is unconfirmed: Phase 9 verifies or installs Docker Engine + Compose v2.
- Public domain with HTTPS via Caddy: users connect from phones outside the office network.
- 20–30 users, plan for heavy use: cursor pagination, indexes, code splitting, thumbnails, perf budgets (ARCHITECTURE → Performance).
- Data isn't highly sensitive: keep the security basics in A10, no extra hardening.
- Password reset by admin-generated one-time link shared over WhatsApp: no SMTP server available. Email can be added later.
- Excel import page added to Phase 7: Sagi has existing Excel sheets.
- Backups moved to a new Phase 10: location to be decided later.
- Stack in CLAUDE.md unchanged.
- Price quotes (2026-10-26, from Sagi): every user, viewers included, can add quotes. Levels: standard (creator + admins, default), public (everyone), admins only (sensitive). Only admins change the level; admins see all. Enforced server-side in Phase 6 (SPEC 5.6). Defaults to confirm with Sagi: new quotes start standard; a creator loses sight of their quote once it's admins-only; public quotes are read-only for non-creators.
- Pinned to well-established majors (TypeScript 5.9, Vite 7, Vitest 3, ESLint 9, Prisma 6): newer majors exist but are fresh; upgrade deliberately later.
- Login rate limit keyed by IP + email: 20–30 users may share one office IP, so a per-IP limit would lock out everyone at once.
- Phase 2 (2026-10-26, from Sagi): ripple uses fade + shrink (no blur); phones stack KPIs, then the grid, then the timeline; SVG stroke animation (draw-in) is allowed and will be revisited.
- Quote visibility field added in Phase 2 (`Quote.visibility`, default STANDARD) so the timeline already hides QUOTE_LINKED events for quotes a user can't see. `Quote.createdById` stays optional until Phase 6 adds the quote screens.
- Second visual style (top photo crossfading to a side photo) comes with uploads in Phase 7, using Sagi's own or dealer-permitted photos only, never manufacturer-site photos. `HeroVisual` is the slot that will take the photos; vehicles without photos keep the drawing.
- Transition budget measured in the page on the production build: about 1.15 s from click until every animation has finished (the e2e test checks stage-mount to settled ≤ 1.1 s on the dev server).
- `packages/shared` is marked side-effect free, so the web bundle only takes the enums it uses (zod stays on the server for now): dashboard JS is 234 KB gzipped.
- Isometric view (2026-10-26, Sagi: the CSS-tilted flat layers didn't look good): each type now also has a small 3D model (boxes, extruded profiles, wheels) projected to an isometric SVG with shaded faces. The transition still tilts the flat top view with CSS 3D (SPEC 5.2 step 3) and hands over to the 3D drawing at the end of the tilt. Pickup side profile shortened.
- Drawings (2026-10-26, Sagi): the real fleet is pickups, 30-tonne class excavators, 20-tonne class wheel loaders and one equipment trailer, and no backhoe. These were drawn first, and `trailer` (an enclosed, caravan-like box trailer) was added as a vehicle type (SPEC A4, glossary נגרר ציוד). Types are modelled once in 3D (metres); their top and side views are generated from the model, except the pickup's, which are hand-drawn. Excavator top views use the arm folded so grid tiles stay readable; the isometric and side views show it extended.
- The Side | Isometric toggle on the vehicle page is in Phase 2 (it decides the last step of the transition); the rest of the vehicle page is Phase 3.
- Colours (2026-10-26, from Sagi): dark theme black and dark grey; light theme a medium-dark grey page with light grey panels; accents machine yellow and red. "Has issues" moved from amber to orange so it never reads as the yellow accent; red stays for "Inoperable". Yellow is too light for text on light grey, so accent text uses a deep ochre (`--fh-accent-ink`).
- Callouts (2026-10-26, from Sagi): engine hours (odometer on road vehicles), VIN, last location, last fuel. The list is one array in `apps/web/src/vehicle/callouts.ts`; any vehicle value can be a callout. A callout with no value (fuel on a trailer) is left out.
- Drawing names (2026-10-26, Sagi saw a compressor drawing under "Backhoe loader"): each drawing now names the type it shows (`represents`), and the registry files it under that name only, so a drawing can't appear under another type. The compressor got its own type (`compressor`, מדחס נייד). Types without a drawing of their own (the backhoe loader) show the generic "other" drawing, a plain crate. The `/drawings` page labels each drawing with the type name users see. The seed has no backhoes any more: two Caterpillar 966 / 330 class machines replace them, and OT-991 became the compressor CP-991.
- Prev / Next order comes from the dashboard tiles already in memory (grid order: type, then serial), so no neighbours endpoint was needed. Navigating replaces the history entry, so Back still leaves the vehicle pages in one step.
- Record panels show the latest events of that kind until Phase 4 brings the full tables.
- Admins need the separate "view start codes" permission to reveal a code; the admin role alone isn't enough.
- Phase 4 (2026-10-26, from Sagi): viewers may add notes and edit or delete their own; every other record needs an editor. Undo lasts 30 seconds. A sudden fuel drop is a fill-up at least 25% worse than the median of the five before it (needs three earlier fill-ups); the numbers are constants in `packages/shared/src/fuel.ts`.
- Deleting a record only marks it deleted and hides its timeline entries (`Event.hiddenAt`); the timeline logs the delete and any restore. Editing a record also updates its own timeline entry so it never shows old values.
- Attachments are recognised by their first bytes (JPEG, PNG, WebP, PDF), up to `UPLOAD_MAX_MB` (20 MB); photos get a 320 px WebP thumbnail. Uploading follows the same rule as editing the record. Receipts (documents) are read-only here until Phase 6.
- Excel file names are ASCII (`PU-901 fuel 2026-10-26.xlsx`): Chromium dropped Hebrew download names in testing. The sheet itself is in the active language.
- The admin status override moved up from Phase 7 to Phase 4, since A7's override rule is part of the status tests.
- Record panels, forms, zod, the chart and ExcelJS load only when a panel opens, so the dashboard bundle doesn't grow.
- Phase 5 (2026-10-26, from Sagi): saved views are shared, everyone can pick any view; its creator or an admin changes or deletes it. Costs in the fleet table cover the last 12 months and the last 3 months.
- The fleet table loads every vehicle in one request and searches, filters, sorts and groups in the browser: tens of vehicles, so it answers instantly; rows are still virtualized so it stays smooth on phones as the fleet grows.
- The fleet table joins the dashboard's persistent layout (`FleetStage`), so the fly-in from a row never unmounts; the vehicle page's Back leads to whichever of the two it was opened from.
- The table's settings live in the URL (`?view=` plus `?s=` for unsaved changes), so Back, reload and shared links keep them. A view's "(changed)" mark shows when the screen differs from the saved view.
- Maintenance cost in the table = service and repair (malfunction) costs, the same rule as the vehicle page's "maintenance cost this year". Receipts join in Phase 6.
- Phase 6 (2026-10-27, from Sagi): new quotes start Standard; creators keep seeing their quote when an admin makes it Admins only, but it is then locked (only admins edit or delete it); public quotes are read-only for non-creators; viewers can add receipts as suggestions that editors and admins approve; unlinked receipts count in the cost columns. Approving or ordering a quote needs an editor or admin.
- Phase 7 (2026-10-27, from Sagi): a re-import updates only the cells the sheet fills; the import covers vehicles, the seven record types and equipment (not receipts or quotes); the photo style shows on the vehicle page only; SVG drawings allowed, cleaned with DOMPurify; users are turned off, never deleted; editors can edit the lists too.
- The account's language and theme win over the device's, so a phone and a PC look the same; "follow this device" is the default until a user picks one.
- Tile drop (2026-10-27, Sagi): the tilted, turning top view still looked flat, so a tile only grows about 10% and glows while a file or item is over it. (The 3D isometric drawings only model the side facing the viewer, so they can't spin a full turn either.)
- Start codes stay out of the fleet table completely, including the "has a start code" flag (SPEC A7).
- Phase 8 (2026-10-28, Sagi): the fake seed's typed text is Hebrew. Typed text is always shown with its own direction (`<bdi>`, or isolates inside translated sentences); only codes are forced left to right.
- Intl formatters are built once per language and options (`lib/intl.ts`): lists format hundreds of dates per render.
- Hebrew tone is neutral everywhere (SPEC A8); the remaining plural instructions ("נסו שוב", "בחרו"…) were rewritten after Phase 8.
- Phones to tune for: Android 3–4 years old and iPhones 2–3 years old (Sagi, 2026-10-28).
- API is bundled with esbuild (workspace code inlined, npm packages external) so `packages/shared` stays plain TypeScript with no build step.
- Phase 9 (2026-10-29, Sagi): the server isn't available yet; installing it is handed off to the server IT team, so this phase delivers everything in the repo plus a handoff. Domain for now: fleet.tfisolutions.com. The server has at least 2 GB of RAM. The first admin is Sagi.
- Images are built on the server itself (no registry), so they come out arm64 there; a private repo is cloned with a read-only deploy key.
- The first admin gets a one-time set-password link from `create-admin`, so no password passes through a terminal or chat.
- Revisions 1 (2026-11-04, from the fleet manager via Sagi): "malfunction icons" = the vehicle's status badge and the Activity list; resize = the report window and the table columns; fuel place is a list plus free text, who and provider typed with suggestions; Diesel and Petrol 95 to start; mandatory switches don't apply to Excel imports; malfunctions get a progress log. Round 2 assumptions (in the plan doc): work cards are their own record kind, editors and admins add them; tools are bucket and hammer (Sagi, 2026-11-05); work cards can gather existing services; the vehicle report is printed to PDF by the browser; extra fields are for location changes only, up to three.
